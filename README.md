# ScamShield — Backend

ScamShield는 화상 통화 중에 상대가 보이스피싱을 시도하는지 실시간으로 판단해, 보호받는 사람에게 확인 질문과 경고를 띄워 주는 서비스다. 2026-2 인하대학교 컴퓨터공학과 캡스톤 프로젝트다.

## 왜 만드는가

보이스피싱은 통화가 끝난 뒤 알아차리면 이미 늦다. 송금이나 앱 설치는 통화 도중에 일어난다. 그래서 통화가 이어지는 동안 대화를 듣고, 위험해지는 순간 바로 알려 주는 것을 목표로 한다.

사기 수법은 일반 전화에서 영상 통화와 화상회의로도 옮겨 가고 있다. 기관을 사칭한 사람이 화면에 나오면 의심하기가 더 어렵다. 우리는 일반 전화망 대신 브라우저 화상 통화를 무대로 삼는다. 브라우저 화상 통화는 양쪽 음성을 서버가 직접 받을 수 있다.

## 무엇에 집중하는가

| 축 | 집중하는 것 | 위치 |
|---|---|---|
| 통화 | 브라우저끼리의 1:1 화상 통화(WebRTC)와 연결 중계(시그널링) | 이 레포 `src/`, FE |
| 실시간 처리 | 양쪽 음성을 화자별로 글자로 바꾸고 순서대로 모아 판단에 넘긴다. **발화가 빠지거나 두 번 들어가지 않게**, 서버가 중간에 죽어도 이어서 처리되게 한다 | 이 레포 `pipeline/` |
| 판단·대응 | 통화 상태를 기억하는 멀티 에이전트(LangGraph): 의심 → 확인 질문 → 외부 조회 → 경고 | [scam-agent](https://github.com/M4-Scamshield/scam-agent) |
| 화면 | 통화 화면 위에 경고와 확인 질문을 띄우고, 사용자의 답을 다시 판단에 반영한다 | [FE_Scamshield](https://github.com/M4-Scamshield/FE_Scamshield) |

탐지 모델 자체의 정확도를 높이는 연구보다는, **실제 통화 흐름 안에서 끊기지 않고 늦지 않게 판단이 돌아가는 구조**를 만드는 데 무게를 둔다.

## 이 레포가 맡는 것

- **통화 연결** (`src/`): 같은 방에 들어온 두 브라우저가 서로를 찾아 연결하도록 신호를 주고받는다.
- **분석 파이프라인** (`pipeline/`): 보호받는 사람의 브라우저가 올리는 음성(내 목소리, 상대 목소리)을 실시간 STT로 글자로 바꾼다. 발화에 순번을 매겨 쌓고, 에이전트에 판단을 맡긴 뒤 결과를 화면으로 밀어 준다.

```
브라우저 A ──(WebRTC 통화)── 브라우저 B
    │ 음성(화자별)                       
    ▼                                    
 분석 파이프라인 ── STT ── 발화 순서 정리 ── 에이전트 판단
    │                                        
    └──── 경고·확인 질문 ────▶ 브라우저 A 화면
```

## 지금 되는 것 / 아직 안 되는 것

**되는 것**
- 1:1 화상 통화 → 실시간 STT → 에이전트 판단 → 경고·확인 질문 표시까지 한 흐름
- 확인 질문에 대한 사용자의 답을 다음 판단에 반영
- 판단이 늦거나 서버가 재시작돼도 발화를 빠뜨리거나 중복하지 않는 처리(테스트로 확인)

**아직 안 되는 것**
- 세 명 이상의 화상회의
- 실제 기관 조회(지금은 모의 조회)
- 서로 다른 모바일망끼리의 통화 연결(TURN 서버 없음)

**앞으로 검토하는 방향**
- 여러 명이 한 사람을 압박하는 화상회의형 사기
- 이미 쓰고 있는 화상회의 서비스에 붙이는 방식(브라우저 확장)
